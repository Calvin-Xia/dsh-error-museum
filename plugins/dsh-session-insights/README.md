# dsh-session-insights · 错误博物馆

把最近 30 天（可切 7 / 30 / 90 天）的 DSH 会话变成一座「错误博物馆」：每一次可确认的失败都是一件**展品**，按模型失败之后的处置分馆陈列，并保留失败前后几笔的真实轨迹。左侧栏面板列表里的入口叫「错误博物馆」。

它回答三个问题：

1. **哪些错误在重复？** 藏品按物种（失败签名）归类，跨会话统计；点任一物种只看这一类。
2. **失败前后发生了什么？** 每件展品带「前因」（失败前的几次调用）、「故障实物」（错误原文）与「后果」（失败之后模型的动作），全部取自会话日志，不猜测。
3. **模型怎么处置错误？** 每件展品被确定性地判定为：换参数重试 / 原样重试 / 换工具 / 交还用户 / 搁置。还会检测**自省（regret）**——模型有没有在继续之前明确写下「我搞错了 / 我忘了 / 不是这个工具」之类的话，并原样引用。

## 展馆结构

| 展厅 | 收录 | 判定依据 |
|---|---|---|
| I 复原室 | 失败被换一种方式解决 | 后续调用成功，且换了参数或换了工具 |
| II 重试室 | 同一动作被重复执行，或同一错误再次出现 | 下一次调用与失败调用参数完全相同（原样重试），或窗口内出现同一物种的失败 |
| III 交还室 | 模型说明后把决定交回用户 | 失败后没有下一次调用，但有面向用户的文字 |
| IV 搁置室 | 线索中断 | 失败后既没有调用也没有文字；或回合异常结束 |

页面上方是馆藏概览（馆藏数 / 复原率 / 自省率 / 原样重试 / 平均复原步数）、**入藏曲线**（每天新增的藏品数量，峰值与近 7 天合计直接标在图上）、藏品类型墙与「策展人按」——四条只根据本期展品统计写成的观察。再往下是**展厅**：一条「馆藏分布」带按数量分段（278 / 170 / 7 / 24 各占其宽），四室各占一条横向展区，标题贴在左侧、展品在其后铺开；数量少的室就是窄的一截，不再是一根空柱子。点开任一展品进入**展签**页：编号、物种、处置判定、错误原文、前因与后果、模型自述，以及一句确定性的策展人按语和该物种的处置建议。

## 陈列方式（为什么不是并排四栏）

展厅的四类处置、会话的三种状态，都是**数量差异很大、而且有先后含义**的序列：复原 278 件 / 重试 170 / 交还 7 / 搁置 24，高痛点 21 / 有冗余 20 / 平稳 46。等宽竖列会让少的一列变成空白、多的一列垂到地上，所以这里换了一套统一的陈列语言：

| 手段 | 用在哪 | 解决什么 |
|---|---|---|
| **比例带** | 展厅、会话看板顶部 | 宽度就是数量：稀有的一类退成窄龛，不平衡变成信息而不是留白；点一段走到对应展区 |
| **横向展区** | 四室展品 | 每室占满页宽、内部网格铺开；一室只有 1 件时那一室就只有一行高 |
| **分级陈列** | 会话看板 | 出问题的逐张展开（卡片），有冗余的排成紧凑行，平稳的排成名录（46 个会话三列收完）；数量大的类型换形式，不加高 |
| **档案页** | 会话详情 | 左侧按时间列出这一会话的每次失败（工具、错误原文、之后怎么处置、几步回到正轨），右侧边栏放现场数据、工具分布、重复调用 |

两处数字要分清：**馆藏**是全量计数（479 件），**陈列**是本期上墙的展品（默认 90 件，每室先展 12 件，其余按「再陈列」补）。

「会话」页签是同一套语言：顶部一条状态带，下面按信号分级陈列（高痛点卡片 / 有冗余紧凑行 / 平稳名录），再加上重复痛点、冗余流程与「用模型深挖」；会话详情即上面那张档案页，每次失败都能直接跳回展签。

## 判定规则（确定性，可复现）

一件展品来自**权威失败信号**：工具结果标记了错误、事件携带错误码、命令以非零码退出，或回合以 error / max-tokens 结束。成功输出从不做关键词扫描——读到一段写着 timeout 的源码不算超时。

- **物种**：`src/pain.js` 里的有序规则（先匹配先赢），如文件在读取后变化、未读取就写入、沙箱拒绝、审批被拒、自动评审拦下/自身故障、路径不存在、命令非零退出、编辑锚点失效、读取越界、空编辑、终端启动失败、超时、传输失败……每种物种带一行处置建议。
- **处置判定**：看失败之后同一回合内的后续调用。参数规范化后比较（键序无关，见 `stableArguments`），相同即「原样重试」，同工具不同参数即「改参数重试」，不同工具即「换工具」；窗口内出现同物种失败则记「再次入馆」；有调用但都没成功、之后有文字，算「交还」。
- **自省检测**：只在失败之后的第一条 assistant 消息里找句子，且要求句子与这次失败相关（提到工具名、错误词或错误文本片段）；强标记（我搞错了 / my mistake / not the read tool / I forgot）记为 `self-correct`，计划性改道（先读再改 / let me re-read / instead）记为 `replan`，只承认错误不说明计划记为 `acknowledge`。引用是该句原文，来源标注 reasoning 或 text。
- **兴趣度与陈列**：每个会话最多保留 8 件最有信息量的展品（认错、反复、原样重试优先）；汇总时每馆预留席位、每种头部物种预留席位，再按兴趣补齐 90 件，所以四个展厅不会被「重试」一类挤满。数字型指标（馆藏、复原率、入藏曲线等）使用全量计数，不受陈列上限影响。

## 读取策略（增量）

读会话日志是这里唯一昂贵的动作，所以每个会话的分析结果（digest，含展品与计数）会**落到磁盘**：`$DSH_HOME/dsh-session-insights/digests.json`，按会话 id 存，带两个判断依据：

- `live`：还在进行中的会话可能继续增长，因此**每次都会重读**；等它关闭后重读最后一次，之后就一直复用。
- `digestVersion`：判定规则变化时我手动加一（当前 3：引入博物馆时 +1，加入按天入藏计数时再 +1），旧缓存自动失效重读，而不是继续报旧数字。

所以第二次打开面板时，通常只有当前活跃的几个会话需要读，其余直接复用摘要；`analyzeSessions` 的聚合本身只有毫秒级。点「刷新」等于忽略缓存全量重读。页头会显示这一轮的实际开销：`摘要缓存：复用 N · 新读 M · 用时 X ms`。

再叠一层进程内报告缓存（`cacheMs`，默认 10 分钟），同一页面反复开关不重复聚合。

## 数据从哪来

全部读取本机会话语料（`ctx.sessionQuery`）。只有点「用模型深挖」时才调用 `ctx.llm.stream`，发送的是**该会话的摘要**（用户消息、折叠后的工具时间线、失败原文），不是完整日志；模型由 `agentDefaultModel.currentSelection()` 决定，不需要在这里填 provider 或 key。分析结果写入 `$DSH_HOME/dsh-session-insights/audits.json`。

## 配置

`cordis.patch.yml` 里该行可调整（都有默认值）：

| 键 | 默认 | 说明 |
|---|---|---|
| `days` | `30` | 默认统计窗口 |
| `maxSessions` | `300` | 单次最多读取多少个会话 |
| `budgetMs` | `25000` | 单次读取时间预算，超出后只分析较新的部分，其余在下次刷新时补齐 |
| `cacheMs` | `600000` | 进程内报告缓存时长 |
| `concurrency` | `4` | 并发读取会话数 |

## 页面状态

`main` 槽同一时刻只渲染一个面板，所以切到对话或别的面板时本页会卸载。它记住自己的位置：页签（展厅/会话）、统计范围、上次打开的会话或展品、物种筛选、是否只看自省、各展区/各层展开到多少，存在浏览器 localStorage（键 `dsh-session-insights.ui.v1`）。下次打开直接回到原处。

## 限制

- 只统计窗口内、被成功读取的会话；读不出的会话会在报告里以 `SESSION_READ_FAILED` 警告列出。
- 处置与自省是确定性规则 + 统计，不做语义判断；语义层面的判断交给「用模型深挖」。
- 展品陈列有上限（默认 90 件，每室先展 12 件），数字指标不受影响；展签只展示失败前后有限的几步（前 3 / 后 4 次调用）。
- reason 里的私有推理只在日志中存在时才被引用；模型没有留下文字时，展签如实写「没有留下文字」。
- 页面依赖 Web 界面；没有 `webServer` 的 profile 里插件保持静默不报错。

## 开发期校验

```powershell
node --check index.js
node --check client.js
node --check src/analysis.js
node --check src/museum.js
```

`_probe/` 下是可独立运行的校验脚本（用 DSH 自带的 Electron node 跑）：

- `run-analysis.mjs`：把分析引擎跑在磁盘上的真实会话日志上，用于在没有安装的情况下调阈值。
- `museum-report.mjs`：在真实日志上构建完整博物馆报告，打印统计、物种、展品与策展人按语，并可写出 `/report` 会返回的 JSON（供预览用）。
- `museum-test.mjs`：用合成日志钉住判定规则——原样重试、改参数复原、换工具、交还、审批被拒、中英文自省、离题推理不引用、失败回合、缓存往返、汇总与均衡陈列。
- `museum-reflection.mjs`：在真实语料上抽查自省检测的样本，用于校准。
- `model-test.mjs`：用假服务校验默认模型解析、reasoning 过滤、流式审计的结束与失败分支。
- `api-test.mjs`：用假 req/res 端到端校验路由、来源围栏、审计持久化与 NDJSON 流。
- `client-test.mjs`：用假浏览器加载真实 `client.js`，校验语言字典、左栏入口、主面板 key，以及页面状态（页签 / 范围 / 当前会话 / 当前展品 / 筛选）的恢复、回退与坏数据容错。
- `incremental-test.mjs`：校验摘要缓存——冷启动全读、已关闭会话复用、跨实例（重启）复用、刷新绕过缓存、版本失效重读。
- `dump-session.mjs`：把一条真实会话导出成 `/session` 会返回的形状，供预览渲染档案页（工具分布、重复调用、用户原话）。

预览（不需要启动 DSH、不需要登录）：

```powershell
node _probe/museum-report.mjs "$env:USERPROFILE\.dsh\sessions" 30 "_preview/report.json"
node _probe/dump-session.mjs "$env:USERPROFILE\.dsh\sessions" "_preview/session-detail.json"
node _probe/build-preview.mjs          # 中文
node _probe/museum-report.mjs "$env:USERPROFILE\.dsh\sessions" 30 "_preview/report-en.json" en
node _probe/build-preview.mjs en       # 英文
node _preview/serve.mjs 4178
# 打开 http://127.0.0.1:4178/_preview/museum.html（英文：museum-en.html?locale=en）
```

`_preview/mini-react.js` 是一个只为预览服务的极小 React 兼容渲染器：它渲染真实 `client.js` 的组件、保留 hook 状态、能点击，所以设计可以在没有 DSH 登录态的情况下用真实报告数据反复截图迭代。
